## 对上一版的纠正

上一版有六套视觉主题，却没有完整说明“什么系统、什么界面、哪些信息、如何操作”。六套配方重复引用同两张技法图，无法作为六种风格的视觉覆盖证据。v1.2.0 增加任务与内容层、正交性有限的多轴分类和可复验的设计审查方法；保留旧配方作为视觉起点。

拟物化描述外观或物件隐喻，世界内界面描述虚构世界关系，两者不能混为一谈。像素是呈现方式，木框/暗石是主题；这些标签也不能代替交互规则。理论依据及局限见 [设计基础](ui-design-foundations.md)。

v1.3.0进一步补上 [项目主题继承](theme-cohesion-contract.md) 和可运行比较：先规定共同色彩角色、光源、材质、边缘、像素策略及文字角色，再允许有依据的用途差异。三种商店结构沿用同一商品与数据，不把“更多风格”实现为逐资产另选画风。验证器只核对合同结构、继承引用与已记录证据；关键参数未定保留 `INCOMPLETE`，视觉缺证保留 `UNDETERMINED`。

## 案例覆盖如何判断

v1.2.0补入 Papers, Please、Return of the Obra Dinn、Loop Hero、Caves of Qud、Factorio、FTL、Inscryption、Dead Space。它们提供文书物件、调查记录、建筑依赖、终端文字、生产信息、升级条件、桌面卡牌和设置页等不同参照。

v1.3.0的 [4组画面研究](visual-game-studies.md) 另从原图观察跨角色一致性；用 `--kind visual-case`、`--list visual-cases` 或 `--id ART-CASE-001` 检索。任务包的 `visual_game_references` 带入相应研究，`theme_cohesion` 提供继承顺序及验证入口，并明确实际项目合同为 `NOT_LOADED`，不会把检索结果伪装成验收。

- **截图仅支持可见状态。** 高亮条目不能证明键盘焦点；显示建筑目录不能证明完整放置流程。
- **证据类型不同。** Factorio 含 2019 年开发者 GUI 设计稿；Dead Space 为官方设置指南截图；不是全部当前版本实机界面。
- **非像素案例是结构比较。** Inscryption / Dead Space 不充当二维像素材制作教程。
- **案例不强塞分类。** 文书核验、卡组配置等任务未被现有 16 类完整细分；未覆盖就记录缺口。
- **风格联系是局部参考。** 没有声称这些游戏采用了本库主题配方，也没有用官方出处替代实际质量评估。

## 仍然缺什么

| 缺口 | 当前可做 | 尚不能声称 |
|---|---|---|
| 完整成品组件与状态图 | 检索方法，提出内容和视觉合同 | 已有六套可直接装入游戏的 UI 资源 |
| 各系统的全过程证据 | 分析已有截图，列出未知项 | 16 类系统都已有完整进入—操作—退出案例 |
| 运行验证范围 | 商店独立小样的实际走查与模型测试，范围见其README | 整个游戏的导航、撤销、存档或16类系统已通过实测 |
| 中文与多设备 | 小样使用真实中文商品、长说明与边界状态，记录实际窗口和输入证据 | 已完成具体游戏的完整本地化、全部设备与手柄测试 |
| 用户体验效果 | 区分静态、走查与目标玩家观察 | 多 agent 审查等于真实用户实验，或拟物必然更沉浸 |
| 风格素材覆盖 | 14个UI案例与另4组画面研究用于比较规律 | 每个视觉值都有开放授权的成套素材 |
| 严格像素生产门槛 | 保留源图、测量与限制；图集软alpha按硬alpha规则失败，逻辑网格待定 | 高分辨率AI像素风图片、最近邻CSS或主题结构通过等于生产级原生像素资产 |

系统模式和评估方法属于有来源约束的原创综合，没有进行系统性文献综述或对照用户实验。制作时应先完成一屏真实内容及异常状态的小样，再扩展成组组件。检查结果必须附实际证据与适用条件。
