# 按任务选择风格并固定美术规范

本文件用于新项目定调、同项目扩充资产、制作变体和修复风格不一致。八种配方在 [style-profiles.json](style-profiles.json)，它们是整理者的工作起点，不是原教程作者的风格分类，也不代表复刻某款游戏。已有项目的确认参考和可运行画面优先于配方建议。

## 先判断正在做什么

| 任务 | 先做什么 | 必须保留的证据 |
|---|---|---|
| 已有场景中新增树、房屋或道具 | 从场景里挑同材质、同尺度的代表物，锁定视角与像素颗粒 | 参考截图、现有资产尺寸/锚点、实际显示倍率 |
| 全新像素游戏定调 | 按题材选1至2个候选配方，做一个相同内容的最小场景比较 | 同内容、同显示大小的试样；选择理由 |
| 同一资产改风格 | 明确允许改变的轴，保留轮廓/构图/尺寸等已要求不变的部分 | 原图、变更约定、同坐标比较 |
| 角色或材质变体 | 共用规范，只改配方允许的颜色/装饰/轮廓变化 | 同族联系表、共同锚点、色板角色 |
| 一致性检查 | 先确认参照对象和检查范围，再比较素材与真实合成场景 | 检查输入、规范版本、标注截图、问题列表 |

当用户只要求局部修复时，不把任务升级为整套风格重做。没有需要改变风格的依据时，选择“沿用当前项目”，无需另选配方。

## 项目主题先于单资产风格

读取 [主题继承合同](theme-cohesion-contract.md) 并维护 [项目主题模板](../assets/templates/theme-contract.json)：项目主题与版本 → `world/character/item-icon/UI/typography` 用途规则 → 单资产的有据例外。已有项目先加载共同规范，新项目先比较项目级候选。下表配方用于这一阶段，不是每次画树、角色、商品图或按钮时各选一次。

未覆盖字段继续继承；用途覆盖需要具体字段、值、理由和证据。单资产例外要限定文件/角色与复验条件，不能静默更换共同色彩角色、光源、投影、轮廓或材质。统一识别语义不等于统一画布：同一商品在世界和背包里应可对应，但图标可以简化细节；UI可用更平静的正面纸面，仍保留项目的材质语法和状态色。

需要看实际游戏怎样建立这些关系时，使用 `python3 scripts/search.py --kind visual-case --task '世界场景与UI的材质和图标一致性' --json`，或读 [4组研究与8张官方远程图](visual-game-studies.md)。它们分别记录原图观察、整理者推论、迁移规则和限制；不是四套可提取的游戏资产。

## 把风格写成可执行的约定

记录实际采用的值和允许例外，而不是只写“高级、治愈、复古”。尚未确认的项保留为 `unresolved`，不能由模板静默猜出硬约束。

| 维度 | 要写清的内容 | 可观察的失败例 |
|---|---|---|
| 投影与尺度 | 俯视/侧视/等距；相同物体的可见顶面比例；人物、门、家具相对尺寸 | 椅子比门还高；同组建筑屋顶比例各异 |
| 逻辑像素 | 世界网格、UI网格、源图尺寸、最终显示倍率 | 一件物体的“像素”比其他物体大一倍 |
| 色板角色 | 阴影、基色、亮部、强调、危险等角色与实际色值 | 金属亮部与天空阴影用同一颜色却无理由 |
| 轮廓 | 外边/内边线重、深综合色或黑色、选择性描边规则 | 新增道具黑边比全场景更厚 |
| 光源 | 主光方向、投影方向、环境色、局部光例外 | 树受左光，旁边房屋受右光 |
| 材质 | 木石金属布料各自的高光宽度、纹理频率、破损尺度 | 石头和金属都有同样镜面白点 |
| 空间与锚点 | 脚底/基底坐标、透明边距、碰撞占地、排序点 | 同一角色换帧时抖动；高树在错误位置遮人 |
| 动画 | 周期、状态标签、帧时长、轮廓/体积保持、次级运动 | 待机周期改变身高；攻击回收跳回站姿 |
| UI | 字体与许可、九宫格、文字区、图标光源、状态语义、输入方式 | UI材质与世界不协调；文字碰到装饰边 |

为不同资产族分别设定画布，不要求房屋、角色和图标全部同尺寸。渲染光晕、半透明特效和独立高分辨率文字可以是明确例外，但必须说明它们如何与主像素层共存。

## 从教程到制作指令

1. 先加载项目主题、目标 role 与允许例外，再根据对象与问题找教程，例如“树冠体积”→ART-011、“细杆与孔洞”→ART-001/004、“俯视攻击”→ANIM-005；读取所需段落及配图，不把整个库塞进上下文。
2. 为本次任务提取具体规则：形体如何分层、哪里应有纹理、哪些像素关系要保留。区分原作者内容与本项目决定。
3. 把已确认的风格约定、目标尺寸、参考图、输出格式与验收条件传给实际制作工具。工具由用户当前项目决定；本配方不绑定某个生成服务。
4. 先在实际尺寸检查一个可复用的小样和场景合成，再在用户已授权的范围内扩展同族资产。发现问题时修改可观察的规则，不反复换一组空泛形容词。
5. 保存源图、导出图、规范版本与引用教程。若在修复既有图像，保留原稿并做同坐标前后比较；不要自动裁掉透明边距或薄杆、提手、孔洞。

可以直接用下面的任务摘要结构；删除不相关字段，不把未确认项作为硬规则：

```text
任务：为现有村庄新增一张独立木凳素材。
依据：项目参考图 + 已确认美术规范；教程ART-014（木材）和ART-004（轮廓）。
固定：视角、逻辑像素颗粒、主光方向、脚底锚点、画布与透明边距。
允许变化：木板接缝、磨损位置和轻微色阶变化。
输出：可编辑源文件、透明PNG、相同坐标的场景合成预览。
检查：支撑杆不断裂，孔洞未堵，木纹不压过大面，放进场景后尺度和受光一致。
```

## 检查结果如何表达

自动检测可以确认尺寸、颜色、透明度等数据是否符合明确约束；它不能证明构图、投影、光源和材质“好看且一致”。视觉检查至少回答以下问题，并给出对应截图或图像区域：

- **同族检查：** 同尺寸显示的联系表中，有无突然变粗的像素、不同线重或异常饱和素材？
- **合成检查：** 放入实际场景后，物体是否落地、尺度合理、遮挡正确，投影能被已知光源解释？
- **跨状态检查：** 动画或UI切换时是否改变体积、锚点或材质语义？
- **修复检查：** 指出的原问题是否消失，同时没有损伤原来正确的薄结构、开口或色板？

结果使用“通过/需修复/未检查/不适用”并附证据。没有看实际画面就写“视觉一致性未检查”，不要用平均颜色接近、色数较少或脚本零报错代替美术通过。

`scripts/validate_theme_contract.py` 只核对主题合同结构、继承引用、来源与已记录证据；结构通过不表示视觉通过。图像硬门槛另用 `audit_assets.py` 按明确规格测量，见 [审阅方法](consistency-review.md)。[乡村商店三个小样](../examples/rural-shop-demo/README.md) 展示同一主题下的布局差异：共用商品图和数据，购买行为共用绿色语义。其AI图集软alpha不符合严格硬alpha要求，且未固定有效像素网格；可以比较界面结构，不应标记为生产级原生像素资产。
