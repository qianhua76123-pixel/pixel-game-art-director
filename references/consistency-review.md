# 美术一致性检查：测量、联系表与视觉审阅

用于检查已经存在的像素素材、动画帧或游戏界面截图。它不会生成、重绘、裁切保存或自动修复源素材。先读取项目实际美术规范；没有规范时先从用户认可的参考图提取可测量约定，并把尚未确认的项目留空。

## 运行与输出

需要 Python 3.9+ 和 Pillow。运行路径相对于本skill根目录：

```bash
python3 scripts/audit_assets.py /path/to/assets \
  --contract /path/to/project-audit.json \
  --out /path/to/audit-output
```

可传多个文件或目录，递归发现PNG、GIF和WebP。自动忽略`._*`文件及本次输出目录。使用 [合同模板](../assets/templates/audit-contract.json) 时先调整角色尺寸和色板；模板的32×32、16色等只是例子，不代表所有像素风都必须如此。

| 产物 | 作用 |
|---|---|
| `report.json` | 原始测量、每项阈值/结果/失败帧号、源图路径与SHA-256 |
| `report.md` | 逐图说明与可点击的原图路径，长逐帧数据指向JSON |
| `contact-sheet.png` | 最多24格的比较图；更多内容生成带序号的后续页 |

每格标注原尺寸、帧号、机器结果、可见边界和实际放大倍数；用最近邻整数放大在棋盘格底上查看。尺寸太大的图只显示标明`1x CROP`的原尺寸局部，必须打开原图查看整体。GIF/WebP抽取首、中、末三个示例帧供联系表使用；机器默认检测全部帧，超过256帧时按总范围等距抽样并返回`INCOMPLETE`。可用`--max-frames 1024`提高上限。

## 结果怎样解释

- `PASS`：仅表示本次已配置的机器规则通过。
- `FAIL`：至少一项明确配置的规则不符合，或图片无法解码。
- `INCOMPLETE`：没有任何可执行规则、没有图像、有无效配置/输入，或未检测全部动画帧。
- `NOT_CONFIGURED`：该图没有适用标准，**不算通过**。
- `overall_status: NEEDS_VISUAL_REVIEW`：脚本始终保持此结论，不能据此声称画风或美术一致性已经通过。

退出码：`0`为机器规则通过、`1`为规则失败、`2`为不完整/无效输入。自动化调用应读取报告，不要把退出码0解释为视觉验收成功。空文件夹不会得到全绿报告。

## 合同格式

顶层包含`schema_version: 1`、可选`project`/`notes`、`defaults`、`roles`和`assets`。规则优先级：默认规则 → 匹配条目的role规则 → 该条目的rules。多个条目按数组顺序应用，后者覆盖前者。嵌套规则对象整体替换，不逐字段合并。

`assets[].pattern`使用Python `fnmatchcase`匹配相对于各输入目录的路径；单文件输入按文件名匹配。`*`也可匹配斜线，因此`characters/*`包括更深子目录。多输入目录出现同名相对路径时会应用相同匹配规则；需要区别时分别运行或改用更明确的目录结构。`role`必须已在`roles`中定义。任何未知检查字段会报错，避免拼错字段后意外放过检查。

```json
{
  "schema_version": 1,
  "defaults": {"alpha_policy": "binary"},
  "roles": {
    "villager": {"canvas_size": [32, 32], "max_colors": 16},
    "building": {"size_multiple": [16, 16], "max_colors": 32}
  },
  "assets": [
    {"pattern": "characters/*", "role": "villager"},
    {"pattern": "houses/*", "role": "building"},
    {"pattern": "effects/*", "rules": {"alpha_policy": "allow_partial"}},
    {"pattern": "houses/special.png", "rules": {"size_multiple": null}}
  ]
}
```

显式`null`禁用继承来的单项规则。`animation_canvas_consistency: false`同样表示不检查，不是通过。

| 规则字段 | 参数 | 实际检验范围 |
|---|---|---|
| `canvas_size` | `[宽, 高]` | 每个解码合成帧的画布尺寸；不是可见物体尺寸 |
| `size_multiple` | `[横向倍数, 纵向倍数]` | 画布是否能被对应倍数整除 |
| `grid_scale` | 正整数N | 以画布原点对齐的N×N块是否重复同一RGBA像素；仅对明确按N倍最近邻放大的导出图使用 |
| `alpha_policy` | `binary` / `allow_partial` / `opaque` | 分别要求只含0/255、允许任意alpha、或全部255 |
| `palette` | `{colors:["#RRGGBB"], max_distance:0}` | 可见RGB到指定调色板的欧氏RGB距离；0表示精确匹配 |
| `max_colors` | 正整数 | 单个合成帧可见RGB颜色数上限；同时报告全动画颜色并集 |
| `margins` | `{min:[左,上,右,下], max:[左,上,右,下]}` | alpha>0包围盒外的透明边距，min/max可只指定一个 |
| `bottom_anchor` | `{padding:像素, tolerance:像素}` | 最低非透明像素与画布底部的间距偏差 |
| `animation_canvas_consistency` | `true` | 同一个动画文件的解码合成帧尺寸是否一致 |

色板检查忽略alpha=0处隐藏RGB；对可见半透明像素仍使用其RGB。RGB距离不等于感知色差，也不是调色质量评分。`grid_scale=1`只表达原尺寸网格，不会识别锯齿好坏、像素簇质量或伪像素风。

底部对齐测量不是识别角色的脚或引擎pivot。阴影、武器拖影、飘带和离地动作都会影响最低像素；为这些素材单独设role或不配置该规则。空透明帧无法测边距，配置了边距/底部规则时会失败。PNG序列被视为独立素材；用相同role和期望画布检查它们，不宣称脚本理解动作组。

## 必须看图的审阅

使用实际输出联系表、同坐标放大局部，以及游戏内的最终合成截图。每个结论记录源图或画面位置、观察到的事实和修复建议。不能只检查颜色数量，也不能把同一张全场景图的切块自动当作可复用tile集。

| 维度 | 要比较的证据 | 常见修复方向 |
|---|---|---|
| 视角与比例 | 屋顶/墙面比例、椭圆、人物可见头顶、角色与门窗尺度 | 统一投影和比例参考，不随意给每张图单独设倾角 |
| 光源与投影 | 主光方向、投影方向和长度、轮廓光与环境光 | 按同一光源校正受光面，保留材质差异 |
| 色彩关系 | 明度层级、饱和度、暖冷关系、场景/角色/UI的视觉重点 | 调整色阶或角色对比，避免仅机械减少颜色 |
| 轮廓与像素簇 | 台阶节奏、细杆、透明孔洞、边缘碎色 | 在原坐标对比局部修复，保留构图和辨识细节 |
| 材质与细节 | 木纹/岩石/叶片的纹理尺度、密度和高光方式 | 降低不必要噪点，按材质保持有区别的表现 |
| 动画与锚点 | 首尾连接、脚接触、重心、头身比例、方向切换 | 修关键帧与时长，不用裁切漂移或新增插值掩盖问题 |
| UI融入与可用性 | 面板边框、九宫格、静区文字、选中/禁用/焦点/错误状态 | 统一组件token；在实际尺寸测试文字和输入，不只评静态皮肤 |

半透明像素可能来自合法发光、烟、水、柔阴影，也可能来自去背残留；脚本报告只说明alpha值。判定白边或污染色需在明/暗底与场景中看边缘。不要一律删掉半透明像素，不要将联系表的灰色棋盘格误当作素材内容。

## 人工审阅记录建议

```text
素材/画面：houses/farmhouse.png，右屋檐
证据：同坐标原尺寸和4倍近邻对比；场景中房屋左上受光，但此屋檐右侧高光更强
判断：光源不一致（视觉观察，非脚本推断）
影响：同场景中突出，破坏统一光照
修复：保留轮廓和尺寸，仅调整屋檐明暗关系
复验：查看修订后同坐标对比和最终场景；未查看前保持待复验
```

机器复检通过后仍打开新联系表和场景截图。没有观察修订结果时，写“修复建议已提供”而不是“已经修好”。
