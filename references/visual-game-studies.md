# 像素游戏 UI 与世界／素材一致性：四组原始图像研究

本组选择四种不同的组织方法：几何母题、纹理分层、按任务划分面板家族、经营与拟物任务。选例依据是可观察的设计取舍，**不是客观排名**。每例两张官方商店原图已实际查看；各图标为 A／B，观察可与 [结构化检索数据](visual-game-studies.json) 对照。

**证据边界：**“观察”只描述图中可见内容；“推论”与迁移规则是原创设计判断。没有从宣传截图反推开发者意图、真实色板数量、精确像素网格或交互效果。原图可能来自不同版本；当前游戏表现可能变化。

**版权边界：**本库只保存链接、哈希与原创评论，商业截图的本地审阅副本留在仓库之外。下列图从官方 CDN 远程引用；第三方截图不属于本库开放许可证，不得提取、描摹或裁切为游戏成品资产。未发现开放再分发许可，不能把“能查看”视为素材授权。

## ART-CASE-001 · Hyper Light Drifter

**研究点：场景几何、荧光强调色与克制的 HUD／图形对话。** 所选图为可见地面与建筑正面的二维俯视倾斜视角；并非只见物体顶面的正俯视，也不据截图断言严格等距投影。

**逐图观察**

- 配色角色（图 A／B）：冷蓝地面提供大面积底色，红披风是人物身份线索；薄荷青、品红与白色出现在 HUD、建筑符号及部分战斗表现中。相同色族跨层出现，但不能据此把所有同色物体解释成同一机制。
- 轮廓与材质（图 A／B）：人物以紧凑色块和深色投影立住；石柱以直边、面分区和稀疏纹样表现结构，树冠以大块剪影配边缘碎簇表现。纹样最密集处集中在局部，没有让全部可行走地面同样繁密。
- UI 框体与图标（图 A／B）：状态 HUD 用矩形块和极简图标；交互泡用直角细框。建筑、地面纹样与这些 UI 都能看到方形／阶梯形的重复，联系来自几何语汇，而非共享一种表面材质。
- 文字与信息密度（图 A／B）：这两图的 UI 主要是图标、分段条和抽象符号，几乎不能提供正文排版样本；战斗信息集中在左上，交互信息靠近人物。不能由这两图推断完整菜单或中文字体表现。

**设计推论与迁移规则**

- 推论：几何母题比把整个 UI 做成场景物件更容易维持画面亲缘感，同时保留 HUD 的清楚边界。
- 推论：红披风作为稳定身份线索，比要求每个地区始终保持同一背景颜色更可迁移；场景分区可以换色，但需要重新检查角色与地面的分离。
- 规则：先规定一组可跨场景和 UI 使用的基础形状，再决定材质。 检查：把建筑纹样、交互提示、状态条并排检查：它们应共享明确的直角／阶梯节奏；不要给单件资产临时追加圆润、金属或卷轴语言。
- 规则：分别规定身份色、环境底色与状态强调色的职责。 检查：在明暗不同的场景中检查角色仍能辨认；危险信息同时使用形状／位置等线索，不能只借用背景中也常见的红色。
- 规则：为活动区域留下纹理密度较低的区域。 检查：用实际玩家、道具和提示同时摆入场景审查，检查焦点周围是否被同亮度碎纹掩埋；不以孤立资产的精细程度代替整体判断。

**乡村游戏落地**

- 固定同一套店主、商品和柜台资产，让招牌、商品选中框、数量按钮共享方角／阶梯节奏；避免每换一个按钮就引用另一款游戏。
- 给常驻货币／时段留紧凑区域，把商品说明靠近当前商品；中文正文仍使用清楚的面板，不模仿抽象文字造成阅读障碍。

**限制与选例判断**

- 静态截图不能证明 HUD 出现时机、动画速度、命中判定或无障碍效果；这里没有把状态条颜色擅自命名为生命或弹药。
- 该游戏的低文字表达不能直接满足乡村商店的价格、库存、说明与中文长文本；必须补充本地化排版与交易反馈。

选它是因为两张图能清楚比较场景纹样、角色身份和小型 UI 的关系。这是对形状组织与视觉取舍的原创判断，不是游戏排名、销量或可用性测试结论。

## ART-CASE-002 · Children of Morta

**研究点：密纹理世界与较简洁的符文框体分层，角色身份贯穿多个尺度。** 所选战斗图是可见地面与人物正面的俯视倾斜视角；角色选择页包含更大的正面人物表现，二者不应按同一资产像素尺寸制作。

原始来源：[开发商／发行商的 Steam 官方商店页](https://store.steampowered.com/app/330020/)；开发者：Dead Mage。审阅日期：2026-10-29。

图 A · 合作战斗截图：深蓝洞窟、暖色局部光与高亮技能；两侧底部 HUD 以同一组件结构出现。 [原图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/330020/ss_83a775e3ef93bde16a08d009a0ad1fb1b2a43b76.1920x1080.jpg?t=1765218667) · [发布页](https://store.steampowered.com/app/330020/)。

图 B · 角色选择页：黑底青色符文框、菱形头像和技能图标；左上 ONLINE CO-OP 为商店宣传叠字。 [原图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/330020/ss_e7bbfd5607b247a6931f521c397bcd50328d45fc.1920x1080.jpg?t=1765218667) · [发布页](https://store.steampowered.com/app/330020/)。

**逐图观察**

- 配色与照明（图 A／B）：战斗图的蓝紫洞窟承接岩石密纹，火把和大范围橙金技能形成暖亮区域，青白粒子也很醒目；菜单以近黑底托住青色线框。相近的青／金色族在世界效果和 UI 中反复出现，但各处面积与亮度不同。
- 轮廓与材质（图 A／B）：岩石、树根、地面有细密的像素纹理；技能图标置于较安静的黑色格内，HUD 外框则有棕金色斜面。菜单人物采用更大、更丰富的明暗表现，仍以服装、发型与肖像对应身份。
- 图形母题与框体（图 A／B）：菱形头像、切角、青色线条及角部符号，在底部战斗 HUD 和角色选择页都出现。主面板没有逐块模仿洞窟岩石，图形关联与材质差异同时存在。
- 字体层级与密度（图 A／B）：角色页用更大的亮色名字、页签和开始按钮，与较小等级／操作说明区分；战斗页同时出现状态、技能、地图、目标和完成提示。前者以分栏和留白组织，后者的高密度需要动态情境检验。

**设计推论与迁移规则**

- 推论：如果世界纹理已很丰富，UI 可以减少内部噪声，只保留边缘母题；让所有面板也铺满同等级纹理，反而可能破坏信息层级。
- 推论：一致性检查应追踪“同一角色在地图、肖像、菜单中的身份”，允许不同呈现尺度；不应把像素尺寸完全相同作为唯一标准。
- 规则：把纹样限制在规定部位，把文字与图标放在安静底面。 检查：将正文背景、边框、角饰分开审查；边角装饰不得侵入数字、技能轮廓或选中边界。
- 规则：建立角色跨尺度身份表。 检查：并列场景小人、头像、对话立绘与菜单人物，检查发型、服装主块、配件、年龄轮廓是否可对应；允许细节数量随显示尺寸变化。
- 规则：为多主体信息重复同一组件结构，并增加非颜色身份线索。 检查：同类角色／顾客卡片的顺序、图标语法和数值位置一致；需要区分主体时同时有名字、编号或形状，不能只换颜色。

**乡村游戏落地**

- 把“青色符文／菱形”换成乡村项目自己的竹编边角、纸签折角或木榫形状，只选一套母题；商品名、价格与库存所在区域保持低纹理。
- 店主的小人、头像和对话像共用一张身份规范；同类商品图标共用视角、明暗方向和轮廓处理，不能分别从不同游戏取样后拼接。

**限制与选例判断**

- 第二图含商店宣传的 ONLINE CO-OP 标记，已明确排除其形状、字体和颜色作为游戏内 UI 依据。
- 两张图不是相同场景与相同时间的严格对照；不能据静帧证明提示不遮挡战斗，也不能把暗背景判定为动态遮罩的实现。
- 所见为拉丁文字与控制器提示，不验证中文排版、键鼠流程或合作可用性。

选它是因为丰富场景、炫亮技能和带纹样 UI 同时存在，可以研究如何让它们建立联系又保持层次；不意味着高装饰密度适合所有项目。

## ART-CASE-003 · Chained Echoes

**研究点：按功能区分浅色对白与深色战斗界面，用角色身份和像素文字连接世界。** 所选场景为二维俯视倾斜表现，可见地面和人物正面；对话头像是独立的大幅人物表现。该案例不能用来直接规定乡村建筑的精确投影角。

原始来源：[开发商／发行商的 Steam 官方商店页](https://store.steampowered.com/app/1229240/)；开发者：Umami Tiger (Matthias Linda)。审阅日期：2026-10-29。

图 A · 夜间剧情截图：浅米色对白框、深色文字与红发肖像，和较暗的林地场景形成层级。 [原图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1229240/ss_b25ed2e671e7b616ec14e7ed3a2f483909e368c4.1920x1080.jpg?t=1788522273) · [发布页](https://store.steampowered.com/app/1229240/)。

![Chained Echoes 图 B：战斗截图：深蓝命令板、细金边、红色姓名条，配合头像状态与顶部行动序列。](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1229240/ss_02152fa16493a1fe30ce307864c7b2d6f82daede.1920x1080.jpg?t=1788522273)

图 B · 战斗截图：深蓝命令板、细金边、红色姓名条，配合头像状态与顶部行动序列。 [原图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1229240/ss_02152fa16493a1fe30ce307864c7b2d6f82daede.1920x1080.jpg?t=1788522273) · [发布页](https://store.steampowered.com/app/1229240/)。

**逐图观察**

- 配色与功能层次（图 A／B）：对白采用浅米色底、深褐字；战斗命令采用深蓝底、白字、金边和红姓名条。两种面板的明暗极性不同，但都用明显边界、细角饰和像素字建立 UI 身份。
- 轮廓、材质与光照（图 A／B）：林叶、巨兽、岩壁和木阶以细密簇块表现材质；UI 正文区域大体平整，装饰靠边缘。夜景相对较暗，对白框很亮；不能仅据此确认有对话期间的动态压暗功能。
- 跨尺度身份（图 A／B）：剧情的红发人物小人和左下大肖像可对应；战斗角色的发色、脸部和服装线索又以小肖像进入状态区与顺序区。图像尺度变化大，身份线索保持连续。
- 字体与信息密度（图 A／B）：对白区优先长句和姓名；战斗区把指令、技能名、费用、资源和顺序分组，正文亮且较粗。顶部行动头像有 Act.／Next 文字，提供颜色之外的顺序线索。此处仅观察到英文。

**设计推论与迁移规则**

- 推论：同一游戏可以使用多个面板家族，只要每个家族对应稳定任务，并共享字形、边界和身份线索；“全部做成同一块木板”并不是一致性的充分条件。
- 推论：头像是世界角色与复杂菜单之间的桥梁；商品也可通过固定轮廓与主色块在货架、背包和交易明细中建立同样联系。
- 规则：为对话、列表与高密度决策分别定义面板用途和明暗关系。 检查：同类任务始终用同一家族；检查新界面是否未经说明就换了字形、内边距语法或边角结构。
- 规则：让人物／物品的跨界面形象保留少量稳定识别特征。 检查：拿同一商品的货架表现、图标和交易明细并排比较形状与主色块；尺寸改变不能让商品变成另一种材质或另一个品种。
- 规则：将装饰与读取任务拆开，按信息类型组织数值。 检查：检查名字、价格、数量、状态是否各有稳定位置；高纹理背景不应穿过正文和关键数字。

**乡村游戏落地**

- 对白用浅纸签、买卖清单用稳定的深色或浅色账页家族均可；先确定用途，再规定每类页面的背景、强调色和字号层级。
- 同一商品在世界货架、购买列表、背包和收据中复用身份规范与图标源，避免每个界面重新生成一套视觉版本。

**限制与选例判断**

- 战斗菜单适合回合决策；不能因此推导实时经营时也能长期占据相同屏幕面积。
- 头像与场景小人无需同尺寸，但共用身份不代表可任意混用插画轮廓、像素簇和写实渲染；例外需要项目规范。
- 截图不能验证中文长文本、连续输入、遮挡恢复或动态可读性。

选它是因为两种明显不同的 UI 家族仍能通过身份、文字和边框语法联系，适合纠正“全屏同材质才算统一”的过度简化。

**逐图观察**

- 配色与光照（图 A／B）：两图均以暖木色吧台、黄橙吊灯、蓝色海景及粉／青霓虹组织餐厅。HUD 的黄色货币边与粉色社交区也使用场景中的亮色族，但文字有独立的黑底承托。
- 轮廓与材质层级（图 A／B）：餐厅角色和家具可见像素轮廓，灯光及背景有较平滑的明暗变化；中央饮品设备的金属表面、螺钉、玻璃与按钮比边缘 HUD 更拟物。统一感并不依赖每层都使用相同纹理或相同像素尺寸。
- 物体提示与系统框体（图 A／B）：点单泡直接靠近顾客，食物图与订单主体相邻；货币、社交、时间与系统入口相对固定在边缘。小游戏在中央放大相关物件，并保留按键、指示箭头和配方示意。
- 字体与密度（图 A／B）：货币数值、系统短标签与小游戏步骤分层；小游戏的结果字大且有描边／倾斜强调。经营图同时存在顾客泡、任务、时间和系统图标，信息丰富，但静帧不能证明忙碌时仍易读。

**设计推论与迁移规则**

- 推论：拟物化适合解释具有实体动作的局部任务；常驻信息采用更轻的图形层，可以让餐厅本身继续承担空间和氛围。
- 推论：世界物件、订单小图、系统图标和小游戏之间可以保持语义一致；它们不必做成同一块木牌，却需要指向同一商品或操作。
- 规则：把常驻状态、对象提示与临时操作分成明确层级。 检查：同时摆入最忙时刻的顾客、订单泡、货币与弹层，检查谁归谁、谁覆盖谁；临时任务结束后应恢复原场景上下文，此项须运行验证。
- 规则：只在能帮助理解动作的局部使用实体隐喻。 检查：秤盘、账本、包装台的形状应说明当前动作；无动作意义的常驻数字无需额外加完整木器或机械外壳。
- 规则：同一物品的世界表现和图标建立明确映射。 检查：从货架到订单到操作台逐项核对品类、轮廓、主色和名称；图标可以简化，但不能换成完全不同的绘画语法。

**乡村游戏落地**

- 让乡村商店的商品询价泡靠近顾客或柜台；钱袋、时段和背包入口常驻边缘。称重、打包或记账再调用与世界道具对应的临时操作层。
- 三种商店方案应沿用同一店主、商品、货架和照明基准，只改变框体／排版／交互隐喻；否则比较混入了资产质量与世界风格差异。

**限制与选例判断**

- 这里选择两张餐厅截图以对应乡村商店主题；没有用它们评价潜水 HUD，也没有覆盖整个游戏。
- 侧视吧台的横向人物关系不能直接复制到俯视商店；应重新验证货架遮挡、空间路径与头顶泡的位置。
- 原图为英文；拟物设备和大结果字不证明触屏、键盘或中文排版都可用，动画／音效和操作成本也未验证。

选它是因为同一经营空间同时容纳局部物件提示、轻量 HUD 和强拟物小游戏，提供具体的界面层级比较；不把混合渲染本身当作高质量保证。

## 用这些案例审查一组乡村商店资产

先拿同一套店主、商品、柜台和背景测试三种 UI，再比较界面的效果。若三个方案连角色、物品、灯光和视角也一起改变，便无法知道改善来自界面还是新资产。

| 审查组 | 应保持的关系 | 允许有理由的差异 |
| --- | --- | --- |
| 店主小人／肖像／对话像 | 发型、服装主块、配件和年龄特征对应 | 显示尺寸与细节数量 |
| 商品实物／列表图标／订单／收据 | 品类、轮廓、主色与名称可相互辨认 | 图标简化与视认尺寸 |
| 世界招牌／菜单框体／提示泡 | 同一组边角、形状和强调色职责 | 实体材质与纯图形界面 |
| 对话／交易／库存／临时操作 | 每种任务内部使用稳定组件与文字层级 | 不同任务可有不同面板家族 |

把这些关系写成项目规范，再给每件资产分配同一个规范版本和所属家族。对照场景整体检查轮廓、光照方向、材质纹理与信息密度；新资产不能仅因为单张精美就通过。最终仍需在可运行界面里验证最长中文商品名、满货架、顾客最多、库存不足与交易反馈等状态。
