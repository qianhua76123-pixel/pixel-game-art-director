# 给其他 agent 的阅读入口

本库是教程知识与素材参考。先检索，再读取相关篇目；不要一次把所有原文装入上下文。

## 推荐读取顺序

1. 读取 [教程目录](CATALOG.md) 或 [机器清单](catalog.json)。每篇记录来源、语言、版本、许可、主题、文件和配图。
2. 用 `id` 或中英主题找到对应 `path`。例如“俯视 行走”“房屋”“无缝 纹理”“碰撞”“像素 缩放”。
3. 先看单篇开头的中文导读、用途、前提与验收，再读取需要的原文小节。
4. 如果具备视觉能力，打开文中相对路径图片。静态关键帧只代表抽样；完整运动顺序查看原GIF。
5. 回答或生成资产时，引用实际用到的篇目ID及原始来源。将作者规则、作者偏好、整理者建议和你的推断分别表述。

## 离线检索

在本库根目录运行，搜索命令只需要 Python 标准库：

```bash
python3 tools/search.py '俯视 行走' --top 5
python3 tools/search.py '房屋' --category drawing --json
python3 tools/search.py 'TileMapLayer' --fulltext --top 5
```

`--fulltext` 会搜索完整Markdown，成本高于元数据检索。默认按标题、主题和学习目标排序，常用中文词会扩展为对应英文词。分词是简单空格分隔和子串匹配，不是向量检索。

## 面向检索系统的数据

| 文件 | 用途 |
|---|---|
| [catalog.json](catalog.json) | 完整篇目列表，包含来源和配图元数据 |
| [catalog.jsonl](catalog.jsonl) | 每行一篇，便于批量导入 |
| [chunks.jsonl](chunks.jsonl) | 按段落与代码围栏切块；每块带来源、许可、版本和文档路径 |
| [manifests](manifests) | 分组采集清单、抓取信息、图像哈希和统计 |
| [验证报告](qa/VALIDATION.md) | 本地链接、元数据、图片与结构检查 |

`chunks.jsonl` 的目标长度是约2200字符，不是token数。长代码块和长表格保持完整，可能超过目标长度。块内相对图片路径应相对于 `relative_link_base` 解析。单篇正文是主档；索引与切块都是可重建派生物。

## 元数据约定

- `id`：固定ID，不使用易变化的标题作为标识。
- `category`：`drawing` / `animation` / `asset-production` / `game-development` / `ui-design`。
- `content_mode`：说明是图片教程中文整理，还是获许可正文转存加中文导读。**不要把中文导读称为整篇原文译本。**
- `version`：软件文档版本或来源固定提交；采集日期不等于作者发布日期。
- `images[].path`：相对于教程库根目录；Markdown里的图片路径相对于所在MD。
- `images[].source_url`、`sha256`：原始出处及本地文件指纹。帧截取图的来源仍指向原GIF。
- `prerequisites`：可能是篇目ID，也可能是技能描述，不能假设全部是可解析ID。

## 应用到像素游戏时

先写清画布、逻辑像素尺寸、视角、统一光源、调色板、锚点和导出约定，再执行教程。俯视角、等距和完全垂直向下不是同一种视角；绘画方法可以借鉴，素材不能不加判断地混用。

保留源文件和原尺寸。避免把软件插值、自动降色、像素画笔或一张完整场景的裁块，直接称为已经合格的可复用像素资产。游戏集成后仍需检查清晰度、透明边缘、碰撞、遮挡、动画状态和实际显示倍率。

本库没有逐一执行每个示例工程，也没有验证每个软件版本的所有按钮。执行代码前检查目标引擎版本与项目结构；在报告中写明哪些步骤实际运行过。
