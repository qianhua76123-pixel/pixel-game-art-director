UI 不只有风格，还有它要帮助玩家完成的事

把视觉表现、世界关系、功能系统、信息内容和输入方式分别设计，再用证据检查。下方是研究图谱与真实参考画面，所示游戏资产属于原作者。

视觉主题，是完整设计中的一层

木框、暗石、全息终端是主题起点；拟物与平面是视觉表现选择。它们都不能替代任务、内容和操作设计。以下八个维度是有来源的工作框架，可组合使用，不是学界统一的八大互斥风格。

拟物 ≠ 世界内界面。纸张菜单可以浮在屏幕上；世界中的终端可以使用平面图形。原始研究也不支持“去掉 HUD 就必然更沉浸”。像素是呈现方式，可与多种视觉语言组合。

先写玩家决策，再安排内容和控件

选择一个系统，查看必须信息、操作和恢复路径。这 16 类是制作工作用的综合模式，并非官方标准分类；机制与数值来自实际项目。

参考的价值，在可观察细节和取舍中

官方游戏截图、开发者设计稿和官方指南截图分别标记。推断与画面事实分开；单张图不能证明焦点、时间策略、中文或真实体验。案例关联表示可参考某些规律，不表示整套视觉同款。

审查结论需要对应证据

静态分析不等于交互验证；多个 agent 的复核也不等于真实玩家实验。不用没有标定的“美术总分”掩盖阻断任务的问题。

证据可以判断仍然未知
官方规范 / 开发者说明明确原则、约束、作者说明在本项目的实际效果
静态图与设计稿布局、层级、可见状态、材质导航、动态、任务成功
原型走查指定构建与条件的操作路径新玩家能否自行发现
目标玩家任务观察样本中的完成、错误与困难未测试人群和条件
机器测量明确技术合同的测量结果完整美术、语义和无障碍通过

把问题写成可复验记录

屏幕 / 状态 / 证据 → 观察 → 对任务的影响 → 修复假设 → 复验方法。只在检查过的条件下标记通过；缺少证据写 UNDETERMINED。固定设备、语言、输入、真实内容和游戏规则后再比较方案。
