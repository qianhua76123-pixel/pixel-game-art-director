## 怎样使用对照板

1. 先看三张等宽 16:9 全图，比较人物、货物、价格、详情和背景的位置。这里的缩略图只支持构图判断。
2. 切换“字体 / 商品图标 / 纸面与框体 / 场景颗粒”，查看两张官方参考、旧稿和新版共四列局部。每个截图像素显示为 2 个 CSS 像素，采用最近邻显示；超宽内容保持真实倍率并允许滚动。
3. 浏览器缩放保持 100%。截图像素不等于游戏逻辑像素；来源截图还可能包含游戏缩放、显示倍率和 JPEG 压缩，不能据此推断原生分辨率或原始图块尺寸。
4. 读取每张图的真实任务与局限。商人制作服务、种子购买与背包不是同一种任务，不能用一个画面的外观证明另一种交互流程。

在仓库根目录可启动本地预览：

```bash
python3 -m http.server 8780
```

访问 `http://127.0.0.1:8780/review/shop-benchmark/`。公开页面只远程引用商业图，离线时需要联网恢复这些来源。

## 具体差距与共同规范

### 构图

**差距：** 旧稿把字段放进大纸面，商人身份主要依靠背景小人物。两张参考都给交易人物安排了明确的视觉角色，并把货目、条件或持有物按用途分开。

**共同规范：** 本轮采用单一 640×360 逻辑画布的柜台选货界面，安排店主、货目、当前商品和费用 / 购买区域。店主等比 contain 到 140×216 逻辑像素，六件商品采用 32×32 逻辑像素图标。整屏只按 1× / 2× / 3× 整数倍率显示，不单独拉伸局部。旧三布局仅保留为历史，不继续并行制作。

**验证：** 在 640×360、1280×720、1920×1080 下检查同一界面，用相同商品、数量和库存定位人物、货物、价格、当前选择和购买后果。本轮结果不表述为完成三套布局。

### 字体

**差距：** 旧稿中文可以阅读，但字体角色尚未与图标、场景的表现建立明确关系。参考中的货名、价格与条件主要靠稳定位置、对齐和重复结构形成层级。

**共同规范：** 中文主体固定为 FusionPixel，12 逻辑像素；整屏 2× 时是 24 屏幕像素。不采用原先 16 / 14 屏幕像素系统字的例外方案。标题、正文与数字沿同一逻辑网格安排，通过位置、留白和颜色职责形成层级。保留字体来源与许可，等待字体加载后再测真实中文；缺字或未加载不能静默换字体并称通过。

**验证：** 字体加载后，测最长商品名、三行说明、最大数量和余额的真实字形、换行、行距与对齐，分别检查整屏 1× / 2× / 3×。本页的 2× 截图局部辅助观察边缘，不能推断字体或资产原生分辨率。

### 素材与材质

**差距：** 旧稿场景纹理细碎、图标高光细密、框体接近平面纯色。共同棕绿色系不足以建立统一的木、纸、布袋和植物表现。

**共同规范：** 店主与六件商品出自同一张新光栅母版。另以母版为参考生成两张光栅资产：室内背景和纸木框，继承共同投影、光照、轮廓、色阶与材质语言。Canvas `drawImage` 只在逻辑网格搬运、裁取并合成新光栅图，不用代码绘制游戏素材。新纸框 source 切边 72 像素，对应 4 逻辑像素边框。

**验证：** 查看母版和两张参考生成图原图及来源，核对店主 contain、六个图标、室内背景及 source 72→4 的纸框角部，再比较身份、轮廓、材质与光照。相同模型或提示词不能替代观察，也不从商业截图提取成品资产。

### 像素颗粒

**差距：** 高分辨率插画像素风、缩小的商品图与 DOM 字体没有共同的逻辑像素基准。统一缩放或设置 `image-rendering: pixelated` 不能代替这项决定。

**共同规范：** 640×360 是本轮渲染逻辑网格，整屏按 1× / 2× / 3× 整数显示，Canvas 合成采用最近邻采样。32 逻辑像素图标、140×216 店主区域、4 逻辑像素框边和 12 逻辑像素 FusionPixel 属于同一渲染约定。严格源图原生网格与 alpha 验收仍未通过；渲染采样正确不等于源图通过生产认证。

**验证：** 渲染检查验证画布、最近邻采样和整屏整数倍率；源素材检查另行验证真实网格、alpha、台阶和细节。技术测量、视觉判断与界面截图分别结论，不以最终像素化外观覆盖源图未通过项。

## 本轮制作与复验顺序

1. 确定同图店主与六件商品的共同母版。
2. 引用母版生成室内背景与纸木框。
3. 在单一 640×360 柜台界面合成，使用 12 逻辑像素 FusionPixel；新稿截图另存，保留此页历史基线。
4. 分别验证整屏整数显示、真实交易状态与仍未通过的源图生产项；不合并成“好看总分”。
